# Project Coordination Controls Evidence Pack

## Classification

**Independent applied case study | Synthetic project data**

This folder contains the inspectable records behind the Construction Project Coordination Controls case study. It demonstrates a complete project-coordination approach without publishing confidential source material or claiming client deployment.

## Start here

1. [`dashboard.html`](dashboard.html) presents the decision-ready weekly coordination view.
2. [`process-map.html`](process-map.html) connects procurement, commitments, meetings, changes, invoices, and closeout.
3. [`project-baseline.md`](project-baseline.md) defines the scenario, scope, authority, milestones, and operating rules.
4. [`rfp-bid-package.html`](rfp-bid-package.html) presents the solicitation and pricing package.
5. [`weekly-meeting-pack.html`](weekly-meeting-pack.html) shows agenda design, minutes, decisions, and action follow-through.

7. [`invoice-routing-control.html`](invoice-routing-control.html) shows the routing gate for a pay application.
8. The CSV registers provide the detailed source records behind the visible pages.

## Role boundary

The Project Coordinator may prepare and organize records, verify administrative completeness, route information, track ownership and deadlines, document decisions, and escalate missing information or risks.

The Project Coordinator does not independently approve contracts, technical direction, changes in scope or price, invoices, payments, final acceptance, or closeout.

## Evidence rules

- All names, dates, organizations, vendors, costs, and project records are fictional.
- The records demonstrate current controls and judgment, not client delivery or approval authority.
- No employer, agency, client, contractor, or team source document is published.
- Practical improvements are shown as controls within an established process, not replacement systems.
- System-of-record updates occur only after authorized action.
